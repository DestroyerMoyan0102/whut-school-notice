# 武汉理工大学校园通知 · 抓取与邮件提醒（V2）

抓取武汉理工大学综合信息网的通知 → 按时间窗口筛选 → 按关键词过滤标题 →
排好顺序 → 发到你的 QQ 邮箱。

已经支持每天 12:00 自动运行，并且**错过会补跑**（关机 / 断网的会在下次开机后补上）。

---

## 一、文件结构

```
D:\school_notice\
├── main.py              程序入口：把整个流程串起来，打印日志、统一报错
├── config.py            【你要改的就是这个】关键词、邮箱、分组顺序、抓取栏目
├── crawler.py           抓取 + 解析：访问网站、翻页、抠出标题/链接/发布时间，并做时间和关键词筛选
├── organizer.py         排序：本科生院 → 信息学院 → 留学交换 → 其他按拼音首字母
├── state.py             状态管理：记住上次跑到哪儿、记录已发过的链接（补跑和去重靠它）
├── email_sender.py      邮件：生成主题和正文 + 通过 QQ 邮箱 SMTP 发送
├── requirements.txt     依赖说明（本程序不需要安装任何第三方库）
├── .gitignore           防止把授权码等敏感信息提交到 Git
│
├── install_task.bat     双击这个 → 安装「每天 12:00」的计划任务
├── uninstall_task.bat   双击这个 → 卸掉计划任务（不会删文件）
├── make_task_xml.py     install_task.bat 会调用它，自动生成 task.xml（不用你管）
├── task.xml             安装时自动生成的任务描述文件（不用你管）
├── state.json           运行时自动生成的状态文件（不用你管，删了也能重新开始）
└── README.md            本文件
```

程序运行时的数据流：

```
config（配置）
  → state（读上次跑到哪儿，算出时间窗口）
  → crawler（抓取 → 时间筛选 → 关键词筛选）
  → state（去掉以前发过的）
  → organizer（排序）
  → email_sender（生成正文 → 发送）
  → state（写回「这次跑到哪儿了」）
```

**所有文件——代码、状态文件、Python 缓存——全部在 D 盘，程序不会往 C 盘写任何东西。**

## 二、站点结构分析结果（实测，不是猜的）

| 项目 | 实际情况 |
| --- | --- |
| 协议 | **只能用 HTTP**：`http://i.whut.edu.cn`。HTTPS(443) 端口不通 |
| 是否需要登录 | 不需要，也不会跳转到登录页 |
| 是否需要 JavaScript | 不需要，通知直接写在 HTML 里 |
| 网页编码 | UTF-8 |
| 反爬限制 | 没有，也没有 robots.txt，服务器是 nginx |
| 通知栏目 | `/xxtg/` 学校通知公告、`/xytg/` 教学科研单位通知公告（含各学院）、`/lgjz/` 学术讲座报告论坛 |
| 分页 | `index.shtml` 第 1 页，`index_1.shtml` 第 2 页，`index_2.shtml` 第 3 页…… |
| 每条通知的位置 | `<ul class="list_t">` 里的 `<li>`：`a.list_text` 是标题和链接，`span.date hidden-xs` 是日期 |

### 重要：网站只提供「日期」，没有「时分」

- 列表页显示：`2026-09-29`
- 详情页也显示：`发布时间：2026-09-29`
- 全站找不到 `2026-09-29 14:32` 这样的精确时间。

所以时间筛选按**日期**比较，规则是「通知日期 ≥ 窗口起点的日期」，宁可多报不可漏报。
多报出来的部分由 `state.py` 的已发送链接清单去重，所以不会重复发。

## 三、邮件里通知的排列顺序

顺序由 `config.py` 的 `PRIORITY_GROUPS` 决定：

| 顺序 | 分组 | 判定方式 | 组内排序 |
| --- | --- | --- | --- |
| 1 | 本科生院 | 标题含「本科生院」 | 按发布日期，新的在前 |
| 2 | 信息学院 | 标题含「信息学院」或「信息工程学院」 | 按发布日期，新的在前 |
| 3 | 留学交换 | 标题含 国际交流 / 出国 / 交换 / 留学 / 访学 / 海外 / 境外 | 按发布日期，新的在前 |
| 4 | 其他 | 剩下全部 | **按拼音首字母**（安…白…陈…董…） |

- 想调整分组顺序 → 在 `config.py` 里上下移动那几行
- 想增删某一组的关键词 → 直接改那一组的 `keywords` 列表
- 拼音排序用的是 Windows 自带的中文排序规则，**不需要装拼音库**

## 四、每天 12:00 自动运行 + 补跑

### 1. 安装

双击 **`install_task.bat`** 就行。它会：

1. 自动找到你的 Python（路径带中文也没问题）
2. 生成 `task.xml`（UTF-16 编码，Windows 计划任务的标准格式）
3. 用 `schtasks` 注册一个名叫 `WHUT_SchoolNotice` 的任务
4. 把任务的详细信息打印出来，让你确认

**第一次自动运行是「明天的 12:00」。**

如果提示创建失败，就右键 `install_task.bat` → **以管理员身份运行**，再来一次。

### 2. 这个任务做了什么

- **触发器**：每天 12:00
- **补跑**：`StartWhenAvailable = true`
  —— 12:00 时电脑关着或睡眠，开机后系统会**尽快把这次补上**（这是 Windows 自带的能力，不需要额外写定时逻辑）
- **断网重试**：任务失败时每 15 分钟重试一次，最多 3 次（应对"那时还没连上校园网"）
- **电池**：允许用电池时启动、切换到电池也不中止
  —— 笔记本默认是不允许的，这里特意打开，否则拔了电源就不跑了
- **不唤醒电脑**：`WakeToRun = false`，不会在你睡觉时把电脑叫醒
- **不重复运行**：`MultipleInstancesPolicy = IgnoreNew`

> 运行时会**短暂弹出一个黑色命令行窗口**，几秒到十几秒后自动关闭。
> 这是故意的：万一出错，你一眼就能看到 `[ERROR]` 的提示，不会静默失败。
> 如果你更希望它完全静默（看不到窗口，也看不到出错信息），告诉我，我改成后台模式。

### 3. 补跑是怎么补的

程序自己会记录「上次成功运行的时间」（存在 `state.json`），所以：

> 9-25 跑过一次 → 之后一直关机 → 9-30 开机
> 这次运行的时间窗口是 **9-25 ～ 9-30**，中间几天漏掉的通知会一起补上

- 最多往前追溯 **14 天**（`config.py` 里的 `MAX_CATCHUP_DAYS`），超过就只补最近 14 天，并在终端提示
- 补跑时邮件主题会写成真实日期范围，例如
  `【校园通知】09月25日-09月30日 新增通知（补跑）`
  日常运行时才是 `【校园通知】过去24小时新增通知`
- 已经发过的通知靠 `state.json` 里的链接清单去重，**不会重复发**

### 4. 常用操作

```bat
REM 立刻手动跑一次（不用等到 12:00）
schtasks /Run /TN "WHUT_SchoolNotice"

REM 看看任务状态和下次运行时间
schtasks /Query /TN "WHUT_SchoolNotice" /FO LIST /V
```

也可以直接双击运行 `python main.py`，两者互不影响。

### 5. 卸载

双击 **`uninstall_task.bat`**。只删计划任务，不会删 D 盘上的任何文件。

## 六、配置 QQ 邮箱

### 1. 拿到授权码

1. 浏览器登录 QQ 邮箱网页版 <https://mail.qq.com>
2. **设置** → **账号**（或「账号与安全」→「安全设置」）
3. 找到 **POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务**，打开 **IMAP/SMTP 服务**
4. 按提示发短信验证，通过后会弹出一串 **16 位授权码**
5. **复制保存好**（只显示一次，之后要看需要重新生成）

> 授权码不是 QQ 密码。QQ 邮箱用 SMTP 发信必须用授权码。

### 2. 把授权码存进环境变量（本机已设置好）

```bat
setx QQ_MAIL_AUTH_CODE "你的16位授权码"
```

执行后**要关掉命令行重新打开**才生效。程序优先读这个环境变量，所以代码里不会出现授权码。

> ⚠️ 如果以后重新设置，注意：**同目录下的 `QQ邮箱授权码.docx` 里是明文授权码**，
> 而 `.gitignore` 只拦住了 `.env` 之类的文件，拦不住 `.docx`。
> 要分享或上传这个文件夹之前，记得把那个 docx 删掉或移出去。

### 3. 填邮箱地址

`config.py` 里已经填好了：

```python
SENDER_EMAIL   = "你的QQ邮箱@qq.com"
RECEIVER_EMAIL = "你的QQ邮箱@qq.com"
```

想发给别的邮箱就改 `RECEIVER_EMAIL`；想发多个就用英文逗号隔开。

### 4. SMTP 服务器（一般不用改）

```python
SMTP_HOST    = "smtp.qq.com"
SMTP_PORT    = 465
SMTP_USE_SSL = True
```

- 465 + SSL（默认）；想改用 587 + STARTTLS 就把端口改成 587、`SMTP_USE_SSL` 改成 `False`
- 腾讯哪天改了服务器或端口，就改这三行

## 十一、报错时应该把什么发给我

把命令行窗口里的**完整输出**复制过来，重点是这些行：

| 你会看到 | 说明 |
| --- | --- |
| `[ERROR] 无法访问学校官网：……` | 网络问题，或没连校园网，或网站改地址了 |
| `[ERROR] 一条通知都没抓到，可能是网站页面结构发生了变化。` | 网站改版了，需要重新分析页面 |
| `[WARN] 这一页没有解析到任何通知，可能是网站页面结构变了：……` | 同上，某一页解析失败 |
| `[WARN] 无法解析发布时间，已跳过：……` | 个别通知的日期格式不认识 |
| `[WARN] 状态文件读取失败，按第一次运行处理：……` | `state.json` 坏了，删掉它会自动重建 |
| `[WARN] 距上次运行太久，已把回溯范围限制在最近 14 天内` | 正常提示，不是错误 |
| `[ERROR] QQ邮箱发送失败：……` | 邮箱配置问题，把冒号后面的原文一起发我 |
| 一堆红字 `Traceback (most recent call last)` | 程序 bug，把整段 Traceback 都发我 |

另外请一并告诉我：运行时间、有没有改过 `config.py`、改了什么。
